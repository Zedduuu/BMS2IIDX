# 更新日志

当前版本：**BETA v0.1.3**

## v0.1.3（2026-11-20）

- 难度槽上方新增「分P」：P1/P2/P3… 各自 5 个 SP + 5 个 DP 槽，点 ＋ 加一份，切页摆谱面，加队列时每个 P 变成独立的一首歌
- 分P 里有谱面时，加入队列会按 P 拆成「曲名P1 / 曲名P2…」，不再靠自动切分（没有拖进槽的才走自动切）
- 修：难度槽区加 P 后按钮位置错乱/出现重复按钮
- 修：队列连续转换时第 2 首起失败（暂存区曲库被下一首清空）——累计库移到暂存区外
- 修：部署抛异常后队列按钮永久锁死（现在会复位并提示）
- 修：关窗时不等后台线程，偶发 QThread 崩溃
- 修：删掉最后一首后，选曲界面残留打不开的幽灵条目（merged XML 没清）
- 修：预览音采样号错位（重映射后按旧号取文件）
- 修：DP 谱面被当成 SP 谱面转换（现在明确拒绝并说明）
- 修：坏判层在 32 代以前的曲库上会写坏文件（现在直接跳过）
- 修：编辑队列项可能改错其它条目；重启后“已转换”但没有 ID 的死条目降级为待转换
- 修：进度条在失败/完成时单位不一致（1% 卡住）
- 修：帮助里 B/L 难度写“26 代起”，实际是 27 代起
- 修：写回曲库时槽表可能被缩小（32 的 omni 自带 99001 示例曲、槽表 100000，以前会缩回 33000 把那条记录截掉）；现在只放大不缩小

## v0.1.2（2026-11-07）

- 更新检查：启动时静默检查新版本，「关于」页也能手动查（可关）
- 关于页新增「更新日志」，不用去网页就能看改了什么
- 修：原版（无 omnimix）模式部署后误报「曲库记录不见了」——自检以前读本体 music_data.bin，现在读 layeredfs 实际生效的 data_mods/<mod>/music_data.bin
- 右上角显示版本与更新状态（已是最新=绿、有新版本=蓝，点击打开下载页）
- 新增「添加更多谱面到队列」：同名的第 2、3 条自动加 P2/P3，已进队列的谱面在列表里标灰
- 修：选 1ST 会落到 34 代文件夹（game_version 写成 `version or self.version`，1ST 的 0 被当成空值 → 34）；现在 0 就是 1ST
- 修：连续部署多首时，后部署的会把先部署的记录整库盖掉；现在逐首并入曲库（本机库缺记录时还会从暂存区曲库兜底，不会再出现“本机库里没有这首歌的记录”）
- 5K 判定改为“有 Key6/Key7 音符才算 7K”，5K 谱面原样转换、不丢音符
- 转换页压缩重排：难度槽变矮、曲目信息与预览图并排、游戏环境与队列按钮并排
- 新图标：手绘藕片（保留原图透明背景，16px 用简化矢量版），窗口、对话框、exe 都换上了
- 超过 5 个谱面自动拆成「曲名P1 / P2…」多首歌（每侧最多 5 个难度槽），队列里就是独立的多首歌，没有额外分组概念
- 只有 1 个谱面时，曲名默认写成「歌名 - 谱名」；开关在「设置 → 转换」，第一次会弹一次说明
- B/L 难度槽改为「27 代起才有」（26 代含以前灰掉）
- 修：队列只有 1 首时进度条显示 1%（范围算错）
- 修：选「1ST」等文件夹时会分到 34xxx 号段、歌却出现在 34 代文件夹；现在严格在所选的千位号段内取号，号段满了会明确提示
- 新增：26 代以前禁用 Beginner / LEGGENDARIA 难度槽（拖进去会被拒绝并说明），避免写出该代不认的槽位
